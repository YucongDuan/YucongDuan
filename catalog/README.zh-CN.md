## 各状态的含义

- **公开源码可见**：初次根目录检查已有源码标记，或后续有源码公开提交回执。目录名不代表软件质量。
- **源码已本地整理**：已整理压缩包中的源码，或包含重点项目源码树；不表示运行过其中代码。
- **源码更新已公开**：回执包含仓库名、明确的发布状态和一致的 40 位提交哈希。仅发布文档的项目仍保留文档分类。
- **仅含文档**：已检查压缩包确认为文档类；初次审计中的 `docs_or_unknown` 仍视为不确定，不会自动改写为仅含文档。
- **已有实际测试回执**：所提供本地运行回执中的指定测试集全部成功执行，测试数大于零且没有跳过。结果仅限回执源码版本及测试范围。Node 中的浏览器逻辑检查不等于完整浏览器渲染测试。
- **本次未运行测试**：本次没有项目执行证据；压缩包内历史报告、测试文件名、声明性通过常量或发布成功都不等于实际测试通过。
- **此包包含本地文件**：生成目录时确实存在于交付包根目录下的项目文件。完整仓库索引不等于全部仓库源码包。
- **已核实公开空仓库**：已连接 GitHub 的仓库及分支检查确认没有分支或源码提交。空仓库保留元数据，不伪造源码 ZIP。

展开每个仓库的证据详情，可查看初次审计的精确版本、源码整理状态、公开提交、可用的 CI 链接、本地入口及测试回执。重点测试对象是 VerityWeave、PACT、MESH²；批量源码迁移项目不会套用这三个项目的测试结果。

## 更新目录

生成器只使用 Python 标准库，不联网，也不执行项目代码：

```bash
python catalog/build_catalog.py --source-root . --bundle-root .
```

`--source-root` 指向审计、整理、快照和发布回执所在目录；`--bundle-root` 指向最终交付包根目录。输出固定写入后者的 `catalog/`。对于暂存交付包，可分别指定这两个位置。只有最终包内真实存在的 `projects/`、`repos/`、`bulk/repositories/仓库名/publish/` 或 `snapshot-rest/repositories/仓库名/` 下已检查的源码视图才会出现离线入口；存在阻塞或凭据待审问题的快照不会得到源码或原 ZIP 链接。

测试默认读取 `receipts/final-integration.json` 及存在时的 `receipts/postpublication-integration.json`，可重复使用 `--test-receipt 相对路径` 指定其他统一复现回执；每个项目采用日期最新的回执。发布回执递归读取 `publication/**/*.json`，包括批量发布子目录，并要求具备仓库、发布状态和提交哈希。目录不推测回执之外的最新远端状态。

请在最终交付目录生成目录，以确保本地文件数量和链接准确；修改页面上的数字不能代替更新回执及重新生成。
