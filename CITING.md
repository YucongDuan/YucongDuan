# Cite the work you used / 引用具体使用的成果

[Research brief](RESEARCH_BRIEF.md) · [Project directory](REPOSITORY_DIRECTORY.md)

| What you used | What to cite |
|---|---|
| A research idea or published result | The original paper, all authors, publication year, venue and DOI where available. Use [DBLP](https://dblp.org/pid/10/2092.html), [Google Scholar](https://scholar.google.com/citations?user=Px89gSoAAAAJ&hl=en) or the publisher to recover metadata. |
| Software or a benchmark | The project's `CITATION.cff` when provided; include the version or commit, repository URL, environment and access date. |
| This portfolio directory | Yucong Duan, *DIKWP Research Hub and Repository Directory*, snapshot dated 8 September 2026, plus the permalink to the commit you consulted. |
| A claim about external use | The original external source and its precise use of the work. The evidence map can help locate that source. |

For a stable GitHub citation, open the relevant file and use its commit permalink. In a cloned repository, `git rev-parse HEAD` reports the commit. Tags and branch contents can change; a commit identifies the evaluated source.

The three new projects supply citation files: [ClearPath](https://github.com/YucongDuan/DIKWP-CLEARPATH-TRANSPARENT-ECONOMY/blob/main/CITATION.cff), [DemandProof](https://github.com/YucongDuan/DIKWP-DEMANDPROOF-COMMONS/blob/main/CITATION.cff) and [LucidEcon](https://github.com/YucongDuan/DIKWP-LUCIDECON-OS/blob/main/CITATION.cff). Follow each project's LICENSE and NOTICE for reuse.

Do not infer a DOI from a project name or replace a paper's coauthors with the repository owner's name. A repository URL identifies a software artifact; it does not imply peer review.
